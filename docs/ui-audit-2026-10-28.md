# UI audit and repair plan

The walkthrough found 24 issues and design gaps, including three crashes with the same native accessibility stack. Fix stability, input, and filter correctness first; then make listening and navigation more complete before tuning the visual details.

**Repairs installed October 29:** Flutter is pinned and runnable; the native accessibility failure, standard Flutter-field editing, restored transport, and the extended query/navigation repairs are installed at `/Applications/Meret.app`. The final pass has 263 passing Flutter tests, 105 passing Rust tests, and ten native seek/search/Settings cycles without accessibility errors. Finding 02 is closed after visual verification. See [Final verification](#final-verification) and [Manual review for October 30](#manual-review-for-october-30).

## Scope and evidence

Audited the installed `/Applications/Meret.app` on macOS on October 28, 2026, with the real library of 844 tracks and 20 releases. The app reports version `1.0.0 (1)`. Source references below use checkout `839a037`; the installed app has no verified revision stamp, so these references identify investigation points rather than prove an exact binary match.

Walked through Today, the Home overlay and rail, Albums and Scores, search suggestions and results, facets and histograms, release/person/game pages, trail branching and the tree, the Keep dialog, Now, playback, listening history, keyboard help, and all eight Settings sections. Playback was exercised briefly and left paused. No library files, settings, or saved trail names were deliberately changed; normal navigation created recent trail entries. The initial audit made no implementation changes; the batch 1 changes are recorded below.

Evidence labels distinguish **observed defects**, **observations needing native confirmation**, **design gaps**, and **source-only findings**. The native audit used accessibility-driven computer control. Direct mouse-only and VoiceOver checks are still needed for the crash and input findings. There is no evidence of library corruption.

Priority: **P1** blocks or undermines a core task; **P2** causes confusion or leaves a common task incomplete; **P3** is polish. These are suggested implementation priorities, not claims that every finding is a regression.

Screenshots remain local audit artifacts and are not included in this commit.

## Stability and input

### 01. P1: The app crashes during ordinary navigation

**Observed under native automation.** Three exits produced `EXC_BAD_ACCESS / SIGSEGV`, invalid address `0x48`. All three faulted in the same main-thread stack:

```text
ui::AXNode::id() const
flutter::AccessibilityBridge::CreateRemoveReparentedNodesUpdate()
flutter::AccessibilityBridge::CommitUpdates()
-[FlutterViewController updateSemantics:]
```

| Local time | Interaction sequence near the crash | macOS report |
| --- | --- | --- |
| 22:17:47 | Leave Settings after visiting its sections, then start search | `meret-2026-10-28-221752.ips` |
| 22:22:03 | Window > Move & Resize > Left | `meret-2026-10-28-222203.ips` |
| 22:23:59 | Resume from Today, then pause/search | `meret-2026-10-28-222400.ips` |

Reports are in `~/Library/Logs/DiagnosticReports/`. A further baseline reproduction at 22:38 produced the same stack. Flutter's slider value-indicator overlay serialized disconnected accessibility nodes; dialog teardown also exposed duplicate and unbuilt nodes. The initial repair contained that overlay locally. The extended pass found another failure after seeking and moving the LCD into its compact search position. The final shared `ThinSlider` draws its track and thumb without an overlay portal, while retaining pointer dragging, keyboard controls, and one adjustable semantics node. The LCD keeps its seek subtree mounted and no longer wraps it in an optional hover tooltip. This addresses the same failure family as [Flutter issue 190357](https://github.com/flutter/flutter/issues/190357).

Regression tests inspect each incremental tree sent to the engine, remove detached subtrees as the engine does, and check for orphan, duplicate, and missing nodes. They exercise every 16 ms animation frame through seeking, query focus/dismissal, Now, Settings, and resizing. Native verification below supplements these tests.

### 02. Closed: Top-bar clicks needed visual verification

**Initial observation corrected.** Automated clicks on the LCD, query, and activity dot appeared to do nothing during the audit. Follow-up checks confirmed query focus, LCD play/pause, and the activity popover. Background title-bar clicks were intercepted by AppKit, and accessibility snapshots sometimes omitted visible popup changes.

No title-bar layout or hit-region change was needed. Keep screenshots alongside accessibility observations when checking these controls.

### 03. P1: Select All did not select search text

**Confirmed and repaired in batch 1.** Focus search, enter `year:banana`, press Cmd+A, then press the physical `x` key. The baseline result was `year:bananax`; native Edit > Select All also failed. The native Edit menu now dispatches through the focused Flutter text model. Select All, copy, cut, paste, Undo, and Redo work in native verification. Native file panels retain their responder-chain routing.

Verification also exposed AppKit restoring an accessibility field editor after Flutter had blurred the field. That stale editor swallowed subsequent shortcuts. The native window now returns key events to the Flutter controller when no Flutter text field is focused. Repeated search dismissal followed by Settings, library navigation, and Keep shortcuts now works without an intervening mouse click.

### 04. P1: The interface has no normal keyboard focus path

**Observed and source-confirmed.** Tab and Shift+Tab do not move focus through controls. [Surface](../apps/meret/lib/shell/surface.dart) explicitly disables traversal and swallows both keys. Custom shortcuts leave many controls unreachable. The native accessibility inspector also exposed only the window container and menus during this audit; that observation needs a separate VoiceOver check.

Restore a predictable focus order, visible focus, and focus return after overlays. Give interactive rows and icons useful semantic labels and actions. Keep the existing shortcuts as additional paths.

**Batch 1 follow-up:** the native tree now exposes the interface, but the inspector still omits the activity popup and can report blank query/dialog values after narrowing the window, while screenshots show the correct text and working editing. Check these with VoiceOver in batch 2; do not infer mouse or editing failures solely from those snapshots.

## Search and filtering

### 05. P1: Histogram interaction replaces the whole search

**Observed and source-confirmed.** Search `tyranny`, enter the results, and select Scores. The table contains 43 tracks. A DR histogram drag changed it to all 844 tracks. The recorded drag did not leave a visible retained range; independently, the implementation confirms the underlying composition defect: [_brush and _brushRecent](../apps/meret/lib/panes/table_pane.dart) emit only the new range clause, or an empty query when cleared. They discard the text query and other filters.

Update only the selected field's clause. Clearing DR must remove DR alone. Cover text + idiom + person/release + range combinations, including a drag that resolves to no range.

### 06. P2: Visible search context can disagree with the results

**Observed and source-confirmed.** After the histogram interaction, the page title and search field still said `tyranny`, and the hit strip still showed its single release, while the table showed all 20 releases. There was no visible effective query explaining the difference.

[SearchPane](../apps/meret/lib/panes/search_pane.dart) stores a local table query while hit loading uses the original widget query. Define which filters apply to each surface, expose active clauses, and make headings, counts, hits, and results agree. This presentation issue needs attention even after filter composition is repaired.

### 07. P2: Query errors truncate the recovery instructions

**Observed and source-confirmed.** `year:banana` produces a red inline explanation that ends mid-syntax. [QueryLine](../apps/meret/lib/shell/query_line.dart) limits it to one ellipsized line. Give the full error room below the input, with an example such as `year:2017` or `year:2000..2020`.

### 08. P2: An empty search offers “All 0 tracks” as an action

**Observed and source-confirmed.** A query with no matches leaves an active-looking “All 0 tracks ↵” row. There is no clear no-results message or useful recovery suggestion. Show “No matches,” preserve the query, and offer an explicit clear or edit path. [QueryLine](../apps/meret/lib/shell/query_line.dart).

### 09. P2: Escape can erase a query the user was editing

**Observed; design decision to revisit.** Escape first dismisses suggestions; the next Escape clears the input. An invalid query can be cleared on the first Escape because suggestions are absent. This loses a draft when the user only wants to leave the field. Preserve text on dismissal and provide an explicit clear action. The current behavior is intentional in [QueryLine](../apps/meret/lib/shell/query_line.dart), so change the interaction contract and its tests together.

## Playback and navigation

### 10. P2: “Play Space” promises the wrong playback action

**Observed and source-confirmed.** Open Tyranny while The Trade Way is loaded. The release's Play button advertises Space, but Space resumes The Trade Way. The global shortcut toggles the existing transport; the displayed button plays the viewed release.

Keep Space consistent as transport control. Remove the hint from the release button or give the release action its own shortcut. Check game and other detail pages using the shared [pane actions](../apps/meret/lib/panes/pane.dart).

### 11. P2: Up next displays tracks but offers no action

**Observed; design gap.** Clicking Randalla's Theme in Up next did nothing. Rows and the extra-items count are plain content in [NowPane](../apps/meret/lib/now/now_pane.dart). Add a clear way to inspect a queued track, jump to it, and expand the queue. Queue editing can be a separate feature; it is not required for the first repair.

### 12. P2: The current song has no direct route to its release

**Observed; design gap.** The Now title and subtitle are passive text. Clicking the song title did nothing, and the LCD leads to Now rather than the release. Add a visible “Go to release” action, or make the release name a clearly interactive link. [NowPane](../apps/meret/lib/now/now_pane.dart).

### 13. P2: Recommendation cards cannot be inspected before playing

**Design gap, source-confirmed.** “Or play something” shows release names and reasons, but its card action immediately starts playback. [PlaySomething](../apps/meret/lib/now/picks.dart) exposes only `playPick`. Add an open-release action and retain an explicit Play action so exploring a recommendation does not require interrupting listening.

### 14. P2: Recent trails are hard to distinguish

**Observed; design gap.** Multiple Home entries shorten to “Tyranny Official Sou...” with the same relative day. Full-title tooltips are absent on these list rows. Show the complete route on hover/focus and enough secondary context to distinguish branches, such as the final stop and time. [Home](../apps/meret/lib/home/home.dart).

### 15. P2: Older trails have no discoverable browse view

**Observed; source-confirmed limit.** Home loads five recent trails and provides no “All trails” or kept-trails browser. This makes older saved work hard to rediscover. Existing back/previous navigation does not serve as a searchable archive. Add an all-trails view with recent/kept filtering and full titles. Avoid expanding this into folders or sync. [Home](../apps/meret/lib/home/home.dart).

## Data clarity

### 16. P2: “This week” includes days from last week

**Observed and source-confirmed.** Today highlighted Wednesday while displaying a large Thursday bar under “this week.” [TodayWeek](../apps/meret/lib/home/week.dart) takes the last seven local calendar days but arranges them Monday through Sunday. That puts older Thursday–Sunday data after the current Wednesday and makes it look like this week's future days.

Use either the current calendar week or a chronological rolling seven-day view with dates and “Last 7 days” wording. Align “Most played this week” with the same period.

### 17. P2: Missing track numbers leak into credits as “0”

**Observed.** An unnumbered release displays a lone `0` beneath its artist credit. Unknown positions should not be shown as a real track number. Prefer “All tracks” when that is established, otherwise a count or omitted position detail. [Release-page construction](../crates/meret-store/src/pages.rs) collects and deduplicates raw positions; inspect the subsequent formatting too.

### 18. P2: The same unnumbered album has two different orders

**Observed and source-confirmed.** Under “library order,” Maelstrom starts with A Lone Tree, Arabesque, and Die Wiederholung. Its release page starts with The Ballerina, Unchained..., and In Fortunae Solo (old). The release query falls back to track ID after position, while the table's library ordering differs.

Define one deterministic fallback for absent disc/track positions and use it in browsing and playback. Do not invent an authoritative album sequence or rewrite tags. Investigate [store pages](../crates/meret-store/src/pages.rs) and [core views](../crates/meret-core/src/views.rs).

### 19. P2: Facet headings show track counts without saying so

**Observed and source-confirmed.** In Albums, “People 67” and “Releases 67” actually mean 67 tracks, even though there are three people and five releases in the visible facets. Label the unit, or show distinct entity counts in headings and labeled track counts in rows. [FacetBrowser](../apps/meret/lib/panes/facet_browser.dart).

### 20. P2: “History” names two different destinations

**Observed; design gap.** H opens listening history. Settings > History is a placeholder for Last.fm and ListenBrainz import, not that history. Rename the setting to “Import listening history” and provide a discoverable entry to actual listening history. [SettingsWindow](../apps/meret/lib/settings/settings_window.dart).

## Visual polish and unfinished surfaces

### 21. P2: Primary navigation repeatedly leads to unavailable features

**Observed; design gap.** Files, History, and Devices are “Coming later” Settings pages. Sources lists numerous unavailable integrations. Release pages display disabled Want and Crate buttons with shortcut hints. This makes the app feel less complete than its working local-player path.

Group planned integrations in a compact “Upcoming” area. Remove unavailable shortcut hints and keep inert actions out of primary action rows, or label their state directly. This cleanup does not require implementing integrations, file editing, devices, crates, or wants.

### 22. P2: Useful metadata is too faint and small

**Observed; design assessment.** Facet counts, section labels, timestamps, and credit provenance are difficult to scan. [Tokens](../apps/meret/lib/theme/tokens.dart) makes the common label 10.5 logical pixels. The nominal faint and dim colors have contrast ratios of approximately 4.1:1 and 2.4:1 against the sky background; actual surfaces and opacity can change those values.

Raise contrast and size for information needed to understand or act. Reserve the dimmest color for decoration. Recheck real screenshots at normal display scale; do not solve this by brightening every divider.

### 23. P3: Sparse searches spend too much height on filters

**Observed; design assessment.** A one-release search reserves a 172-pixel facet browser, four histograms, and surrounding headings/gaps. Most facet space is empty while the track list starts roughly 400 pixels down the window. Offer a compact or collapsible filter region and make active filters visible when collapsed. [FacetBrowser](../apps/meret/lib/panes/facet_browser.dart) and [TablePane](../apps/meret/lib/panes/table_pane.dart).

### 24. P3: The intended fonts are not bundled

**Source-only finding.** Tokens name Instrument Sans and Geist Mono and contain a TODO to bundle them. [pubspec.yaml](../apps/meret/pubspec.yaml) declares no font assets. Typography therefore depends on font availability/fallback; the precise font rendered in this session was not identified. Bundle the intended licensed assets, then verify truncation, alignment, and small labels across supported platforms.
